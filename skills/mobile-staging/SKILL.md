# Mobile staging

## Inputs and deliverable

- Accept: scene path; locations; actions; camera constraints.
- Produce: start-end positions, path, beat transitions and coverage alternatives.
- If critical inputs are missing, state assumptions, distinguish planning from observed footage, and mark any untestable decision for review. Do not invent measurements, assets or runtime results.

## Decision procedure

1. Divide movement into meaningful changes of dramatic relationship rather than distances alone.
2. Decide whether the camera stays while subjects change grouping, follows them, or cuts to a new viewpoint.
3. Map visibility, focus, screen direction, speed, foreground occlusion and lighting along the path.
4. Plan transitions between stable arrangements, retaining a visual reference or establishing a new axis as needed.
5. Create a coverage fallback for a complex move and test with a rough animatic or rehearsal.

## Diagnose and correct

If movement looks like wandering, give each change of position a motivation. If a track hides reactions, pause, reframe or split the move.

## Output checks

- Deliver the specified artifact, with decisions tied to identifiable scenes, beats or shots when relevant.
- Show evidence or reasoning for the selected approach and at least one plausible alternative when the decision is consequential; state whether it is planned or actually observed.
- Verify the specific failure mode above is not present, or document the creative reason and the test that would demonstrate success.
- Use the original practice case below to check that the procedure produces a concrete, reviewable result rather than a definition or generic advice.

## Practice case

Two coworkers walk from a desk to a window while negotiating; track only if the path communicates changing alignment.
