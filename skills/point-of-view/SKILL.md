# Point of view

## Inputs and deliverable

- Accept: story viewpoint; audience knowledge; scene geography.
- Produce: POV map, look-target-reaction sequence, viewpoint rules.
- If critical inputs are missing, state assumptions, distinguish planning from observed footage, and mark any untestable decision for review. Do not invent measurements, assets or runtime results.

## Decision procedure

1. Distinguish detached observation, camera near a character's viewpoint, and literal subjective vision; specify the intended audience relation.
2. If a character's look motivates the next shot, establish gaze direction, height, and plausible target location.
3. Choose whether to show the look before the object, the object before the reaction, or withhold the target for suspense.
4. Use direct lens address only when deliberate; differentiate a subjective shot from an over-the-shoulder view.
5. Return to an objective or shared view when perspective needs clarification.

## Diagnose and correct

A direct-to-camera glance can accidentally break immersion; correct gaze placement unless direct address is intended.

## Output checks

- Deliver the specified artifact, with decisions tied to identifiable scenes, beats or shots when relevant.
- Show evidence or reasoning for the selected approach and at least one plausible alternative when the decision is consequential; state whether it is planned or actually observed.
- Verify the specific failure mode above is not present, or document the creative reason and the test that would demonstrate success.
- Use the original practice case below to check that the procedure produces a concrete, reviewable result rather than a definition or generic advice.

## Practice case

A person hears a noise behind a door; plan objective, near-character and literal POV alternatives and select for uncertainty.
